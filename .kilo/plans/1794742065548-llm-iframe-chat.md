# Chat-Ersetzung: LLM-seitiges UI im iframe mit /signon-Vorschaltung

## Kontext

- Heute: `ChatComponent` (DxChat, `libs/dx-renderer/src/lib/components/chat/`) → `CHAT_SERVICE` (`DefaultChatService`) → `AI_CHAT_API` (`provideOpenAiResponsesApi`, Base `BALLWARE_AIURL` = `http://localhost:5010/ai`).
- Referenzmuster: Reporting Viewer/Designer via Signon — `libs/rest-meta-api/src/lib/document.ts` (`viewerUrl`/`designerUrl`) und `PrintComponent` (`libs/dx-renderer/src/lib/application/print/print.component.ts:29-35`): `signonUrl/<token>?redirect=<ziel>` → iframe.
- Ziel: Chat-UI kommt vom LLM-Service auf `http://localhost:3004` und wird per iframe über `/chat/<Kontext>` eingebunden; vorgeschalteter `/signon`-Aufruf.

## Festgelegte Entscheidungen

1. **Komplette Entfernung** der client-seitigen Chat-Infrastruktur (DxChat-UI, `CHAT_SERVICE`, `AiChatApi` Alt-Adapter, OpenAI/SignalR-Provider).
2. **Token-Typ: `idToken`** (`identityService.idToken$`), analog Document-Viewer.
3. **Konfiguration: zwei neue ENV-Variablen** `BALLWARE_AI_SIGNON_URL`, `BALLWARE_AI_CHAT_URL`; `BALLWARE_AIURL` (5010/ai) bleibt für die Origin-/Embedding-API (`provideAiRestApi` → `AI_ORIGIN_API`) unangetastet.
4. **URL-Building nach Meta-Api-Muster**: Interface in `meta-api`, Implementierung in `rest-meta-api`, Provider-Funktion; Component kombiniert `idToken$` + Context wie `PrintComponent`.

## Signon-URL-Schema (Annahme: identisches Kontrakt-Muster wie Document-Signon)

```
${signonUrl}/${encodeURIComponent(idToken)}?redirect=${chatBaseUrl}/${encodeURIComponent(context)}
```

Lokales Beispiel:
`http://localhost:3004/signon/<idToken>?redirect=http%3A%2F%2Flocalhost%3A3004%2Fchat%2Fglobal`

## Fehlermodi / Edge cases

- `idToken` noch undefiniert → iframe nicht gerendert, Platzhalter; URL entsteht erst mit Token (`of(null)`-Zweig).
- Token-Refresh (`idToken$` emittiert neu) → URL wird neu gebaut, iframe lädt mit frischem Signon (wie Print-Viewer). Gesprächskontinuität liegt beim LLM-Service (Session hinter Signon) — clientseitig kein Conversation-States mehr.
- Kontextwechsel Route `/chat/:x` → `NoReuseOnParamChangeStrategy` erzwingt Neueszeugung, neuer iframe-Load.
- LLM-Service nicht erreichbar → Browser-Fehlerseite im iframe; kein gesonderter Handler (bewusst out of scope).
